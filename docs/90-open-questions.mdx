## Q1：Python 工具鏈與目錄佈局

**題目**：用 uv 還是 pip／venv？Python 版本？實驗程式放哪個目錄、怎麼分層？

**為什麼現在要決定**：`CLAUDE.md` 原本寫「等寫第一行實驗程式碼時再定，不預先猜」。那個時間點就是現在——10/26–11/01 這格要產出 split、reveal manifest 與 TF-IDF 特徵。

**影響範圍**：研究規格 11.2、所有實驗程式、可重現性宣稱。

**可選方案**：

| 方案 | 優點 | 代價 |
| --- | --- | --- |
| uv + `src/splitsense/` 套件佈局 | 鎖定版本快、重現性好、與 `pyproject.toml` 一致 | 需要先學工具 |
| pip + venv + `requirements.txt` | 最熟悉、課堂示範常見 | 版本鎖定較弱 |
| 只用 notebook，不建套件 | 最快出圖、簡報素材直接來自 notebook | 洩漏檢查測試難寫，重跑一致性難保證 |

**狀態**：:badge[待拍板]{variant="danger"}

## Q2：繁中 pilot 是否與課堂版並行啟動

**題目**：繁中 pilot 照 10/19 定案擱到 12/21 之後，還是現在就開始招募標註者？

**為什麼是個問題**：招募 3 至 5 位組外標註者、寫標註規範、做 20–30 筆校準，前置期很長。若論文確定要做，現在開始的成本遠低於期末後才開始；但那會吃掉課堂版的時間，而課堂版目前已落後約一週。

**影響範圍**：研究規格 4.1、6.5、10.2。

**狀態**：:badge[待拍板]{variant="danger"}

## Q3：階梯 3 選 Random Forest 還是 Gradient Boosting

**題目**：研究規格 7.1 寫「Random Forest 或 Gradient Boosting」，要選哪一個？

**影響範圍**：調參格線（RF 調 `n_estimators`、`max_depth`；GB 調 `n_estimators`、`learning_rate`、`max_depth`）、`GridSearchCV` 的執行時間。

**提醒**：進度落後時的刪減順序第 2 條是「樹模型只留一個」，所以即使兩個都做，也要先決定哪一個是會留下來的那個。

**狀態**：:badge[待拍板]{variant="warning"}

## Q4：TF-IDF 的具體設定

**題目**：`ngram_range`、`min_df`、`max_features`、是否 sublinear scaling、是否移除 stopwords？

**為什麼不能隨便填**：文字中位數只有 60 字元（見 Dataset Card 第 3 節），很短。`max_features` 開太大在這種短文本上多半只是增加噪音與調參時間。

**影響範圍**：研究規格 7.2、整個課堂版主線的特徵。

**注意**：這些設定屬於特徵決策，**只能由 training 決定**（研究規格 6.4 第 6 條）。

**狀態**：:badge[待拍板]{variant="warning"}

## Q5：163 筆重複文字要去重還是合併

**題目**：31,766 個 item 對應 31,603 段不同文字。重複的要整段丟掉、保留其中一筆，還是把多個 item 的標註合併成一筆？

**影響範圍**：研究規格 6.2、split manifest、item 總數與所有統計。

**約束**：無論選哪個，都必須在切 split 前完成，避免同一段文字同時落在 train 與 test。合併會讓該 item 的標註數不等於 3，與「只取恰好 3 份」的前提衝突，需額外處理。

**狀態**：:badge[待拍板]{variant="warning"}

## Q6：OpenSpec 是否在課堂版期間續用

**題目**：repo 已導入 OpenSpec（commit `abb2898`），`openspec/config.yaml` 宣告 `openspec/specs/` 擁有實驗程式的行為。課堂版期間要實際使用，還是暫停？

**影響範圍**：開發流程、`openspec/config.yaml`、`CLAUDE.md` 的文件分工敘述、研究規格 1.2。

**討論結論（2026-10-29，待確認）**：課堂版期間暫停使用，12/21 之後若接論文延伸再評估。理由是單人、六週、程式不列入交件的情況下，「筆記 → 研究規格 → SHALL/Scenario → 程式」四層的比例不對，而目前的首要風險正是時間花在文件而非程式。唯一值得規格化的洩漏檢查（研究規格 6.4）已是七條編號清單，可直接對應測試案例，不需要中間層。

**若確認暫停，必須同步處理**：`openspec/config.yaml` 與 `CLAUDE.md` 需註明暫停，否則 repo 會聲稱一件沒在做的事。

**狀態**：:badge[討論中]{variant="info"}

## Q7：繁中 pilot 的題目來源

**題目**：150–300 筆繁中文字從哪裡來？

**約束**（研究規格 6.5）：題目必須貼近論文主要使用情境，不能只為了方便而選與產品無關的情緒分類。原始文字與 annotator 身分只存本機。

**已排除**：簡體中文資料與機器翻譯資料不能當繁中主證據；[`YACLC`](https://github.com/blcuicall/YACLC) 等中文多標註資料可作方法備援調研，但它是中文學習者語料且任務不同，不能取代臺灣繁中 pilot。

**狀態**：:badge[待拍板]{variant="neutral"}（論文階段再處理，但與 Q2 連動）

## Q9：零樣本 LLM 對照線是否納入課堂版

**題目**：研究規格 7.1 的階梯 4 標為課堂版選做。做還是不做？

**兩面**：同儕與教師很可能會問「這個 LLM 不是早就會了嗎」，有一條對照線回答起來比較完整。但它不在不可刪除清單上，而 11/16–11/22 那格已經被 BGE-M3 比較佔住，兩者可能只能擇一。

**必要前提**：若要做，必須同時寫明資料污染風險（研究規格 4.3、7.6），否則分數不可檢驗。
