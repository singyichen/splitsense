# SplitSense（歧見預判）

機器學習實作課程期末專題。只看到每筆資料的前 2 份標註時，預測哪些 item 的完整標註會出現:ref[標註分歧]{id="term.annotation-disagreement"}，把它們排在前面，讓有限的:ref[複核預算]{id="term.review-budget"}花在最可能出問題的地方。

目標是**排序**，不是判斷哪個標籤正確。課堂版只做英文（GoEmotions，取自 :ref[TID-8]{id="term.tid-8"}）。

## 三個發現

主要指標是 :ref[Recall@10%]{id="term.recall-at-k"}，在:ref[難題子集]{id="term.hard-subset"}（可見 2 份一致）上計算；整個 test split 上這個指標已經飽和，理由見[研究規格 8.2.1](./00-research-spec.mdx)。

1. **可見 entropy 在 hard 子集等於隨機。** 兩份可見標註一致時 entropy 恆為 0，排序全靠同分打散。拿它當「不用 ML」的對照，會高估模型的貢獻。
2. **「一張四列查表拿到模型 95% 的效果」要看跟哪個模型比。** 只看「前兩人同意了哪個標籤」的先驗是 18.5%，TF-IDF Logistic Regression 是 19.3%（查表佔 95.9%）——但換成 `bge-m3` 的文字表示之後是 21.8%，查表只佔 84.9%。
3. **文字表示是比模型族更有效的槓桿。** 同一個 Logistic Regression 只換文字表示：配對比較 +2.45 ± 0.72 個百分點，5 個 :ref[reveal seed]{id="term.reveal-seed"} 全勝；把 LR 換成 Gradient Boosting 是 +0.05 ± 0.27、2/5，與 0 分不出來。
